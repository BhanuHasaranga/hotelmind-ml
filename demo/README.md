# Demo Assets

Real request/response pairs for all 5 Phase 4 prediction endpoints — every
file here was generated by starting the live API (`uvicorn api.main:app`)
against the actually-trained models under `models/*.pkl` and issuing real
HTTP requests. Nothing in `sample_requests/` or `sample_responses/` is a
placeholder or hand-written mock.

## How these were generated

```bash
uvicorn api.main:app --port 8124 &

curl -s -X POST http://127.0.0.1:8124/predict/occupancy  -H "Content-Type: application/json" -d @demo/sample_requests/occupancy.json
curl -s -X POST http://127.0.0.1:8124/predict/pricing    -H "Content-Type: application/json" -d @demo/sample_requests/pricing.json
curl -s -X POST http://127.0.0.1:8124/predict/restaurant -H "Content-Type: application/json" -d @demo/sample_requests/restaurant.json
curl -s -X POST http://127.0.0.1:8124/predict/staff      -H "Content-Type: application/json" -d @demo/sample_requests/staff.json
curl -s -X POST http://127.0.0.1:8124/predict/churn      -H "Content-Type: application/json" -d @demo/sample_requests/churn.json
```

`scripts/predict_examples.py` reruns this exact flow programmatically — see
the repository root `scripts/` folder.

## Notes on the values used

- **Dates** (`2017-09-15` for pricing/restaurant/staff) fall inside the
  canonical dataset's real range (2015-07-01 to 2017-09-13) plus a couple of
  days — chosen so the request is realistic relative to the training data,
  not because the API requires it (pricing/restaurant/staff take contextual
  features as direct request fields, not a lookup by date).
- **Occupancy's forecast dates** in the response start the day after the
  trained Prophet model's own training data ends, not the request date —
  this is intentional (see `reports/final_phase4/known_limitations.md`
  item 12) and the response reflects it faithfully.
- **`guest_id: "33462606499639"`** is a real `guest_id` value present in
  `data/warehouse/dim_guest.parquet` (verified to exist before use).
- Full endpoint documentation, including every field's meaning and
  validation rules, lives in `docs/api/`.
