# Feature Dataset Inventory

Generated by `src/pipelines/feature_engineering.py`, run against the only
sanctioned Phase 4 inputs: `data/processed/hotel_bookings_clean.parquet`
and `data/warehouse/{dim_date,dim_hotel,dim_guest,dim_room_type,
fact_booking}.parquet`. No raw CSVs were read directly. Source files
(`data/features/*.parquet`) were profiled directly — no fields below are
estimated.

---

## 1. `occupancy_features.parquet`

- **Rows:** 1,605 &nbsp; **Columns:** 28 &nbsp; **Grain:** one row per (branch, date)
- **Date range:** 2015-07-01 → 2017-09-13 (branch 1: 806 rows, branch 2: 799 rows)
- Not present anywhere upstream as a table — this is the daily "mart"
  derived in-process from `fact_booking`'s per-booking grain (see
  `src/features/occupancy_aggregation.py`). No live Postgres warehouse
  connection was used.

| Column | Type | Notes |
|---|---|---|
| branch_id | int | =`dim_hotel.hotel_key` |
| occupancy_date | date | derived from expanding each booking's check-in→check-out range |
| occupied_rooms | int | count of occupied-room-nights that day |
| total_rooms | int | fixed capacity constant per hotel — **assumption, not measured** (see `known_limitations.md`) |
| occupancy_pct | float | 0.67 – 92.0, mean 57.2, std 22.1 |
| total_revenue / revenue_7day_avg | float | sum/rolling-mean of `avg_daily_rate` across occupied nights |
| occupancy_7day_avg / occupancy_30day_avg | float | trailing rolling means, `shift(1)` to avoid leakage |
| month, quarter, day_of_week, is_weekend, season | int/str | `src/features/calendar_features.py` |
| is_public_holiday, is_local_event, event_name, is_holiday, is_event | int/str | joined from `data/raw/events_holiday_calendar.csv` seed |
| occupancy_pct_lag_1 / _7 / _30 | float | `src/features/time_series_features.py::add_lag_features` |
| occupancy_pct_rolling_mean_7 / _30 | float | same module, `add_rolling_features` |
| occupancy_trend | float | `occupancy_pct - occupancy_7day_avg` |
| revenue_trend | float | `total_revenue - revenue_7day_avg` |

## 2. `pricing_features.parquet`

- **Rows:** 6,420 &nbsp; **Columns:** 24 &nbsp; **Grain:** one row per (branch, date, room_type) — cross-joined against the 3 warehouse room types (Standard/Deluxe/Suite) via `dim_room_type.parquet`, hence 4× `occupancy_features`' row count (1,605 × 4 = 6,420)
- Shares the same daily occupancy/revenue base as `occupancy_features.parquet`.
- `base_price_multiplier` sourced from `data/warehouse/dim_room_type.parquet` (single source of truth; the old raw-CSV seed `data/raw/room_type_dim.csv` is no longer read by pricing code).

| Column | Type | Notes |
|---|---|---|
| demand_index | float | `occupancy_pct * (total_revenue / revenue_7day_avg)` — proxy, no direct demand measure exists |
| room_type_name | categorical | Standard / Deluxe / Suite |
| base_price_multiplier | float | 1.0 / 1.4 / 2.0 |
| *(remaining 21 columns)* | | same calendar/occupancy columns as `occupancy_features.parquet` |

## 3. `restaurant_features.parquet`

- **Rows:** 1,605 &nbsp; **Columns:** 28 &nbsp; **Grain:** one row per (branch, date)
- **Entirely synthetic** — no restaurant order data exists anywhere in this
  project. Source: `data/raw/restaurant_daily_synthetic.csv`, generated by
  `src/pipelines/synthetic_data.py::generate_restaurant_daily`, deterministic
  and seeded (`seed=42`), driven by real derived `occupied_rooms` rather than
  pure noise.

| Column | Type | Notes |
|---|---|---|
| breakfast_revenue, lunch_revenue, dinner_revenue, total_revenue | float | synthetic, `base_rate[meal] * occupied_rooms * day_of_week_multiplier * (1 + noise)` |
| avg_item_value | float | fixed constant (mean of per-meal item values) |
| items_sold, total_orders | int | `total_revenue / avg_item_value`, rounded |
| breakfast_qty / lunch_qty / dinner_qty | float | `derive_meal_quantities` revenue-share estimate |
| breakfast_qty_check / lunch_qty_check / dinner_qty_check | float | cross-check via `meal_revenue / avg_item_value`; sample rows show &lt;1% divergence between the two estimates (e.g. 18.35 vs 18.21) |
| total_orders_lag_1 / _7, total_orders_rolling_mean_7 | float | `time_series_features.py` |

## 4. `staff_features.parquet`

- **Rows:** 4,815 &nbsp; **Columns:** 21 &nbsp; **Grain:** one row per (branch, date, department) — 1,605 dates × 3 departments (Reception, Kitchen, Housekeeping)
- **Entirely synthetic** — no staff attendance data exists anywhere in this
  project. Source: `data/raw/staffing_daily_synthetic.csv`, generated by
  `src/pipelines/synthetic_data.py::generate_staffing_daily`, same
  deterministic/occupancy-driven approach as the restaurant seed.

| Column | Type | Notes |
|---|---|---|
| department_name, department_id | str/int | Reception=1, Kitchen=2, Housekeeping=3 |
| present_employees | int | synthetic, `ratio[dept] * occupied_rooms * day_of_week_multiplier` + small integer noise |
| scheduled_employees | int | synthetic, same base without noise |
| present_employees_lag_1 / _7 / _30, present_employees_rolling_mean_7 / _30 | float | grouped by `department_id` |

## 5. `churn_features.parquet`

- **Rows:** 5,672 &nbsp; **Columns:** 16 &nbsp; **Grain:** one row per guest
- **Grain matches `dim_guest.parquet` exactly** (5,672 guest profile clusters
  — see `reports/warehouse_loading/key_generation.md` for how `guest_key` is
  derived; it is a booking-profile hash, not a true individual identity).

| Column | Type | Notes |
|---|---|---|
| lifetime_bookings, lifetime_spend, first_stay_date, last_stay_date | | direct from `dim_guest.parquet` |
| total_nights | int | aggregated from `fact_booking.nights` per `guest_key` |
| cancellation_ratio | float | share of a guest's bookings with `reservation_status == "Canceled"` |
| repeat_guest | int (0/1) | `lifetime_bookings > 1` |
| recency_days | int | 1 – 793, mean 302.6 — anchored to the dataset's own date range, not the real clock (see `known_limitations.md`) |
| churn | int (0/1) | 3,414 churned (60.2%) / 2,258 not churned (39.8%) — `recency_days > 180` |
| frequency, monetary, avg_spend_per_stay | | `src/features/churn_features.py::add_rfm_features` |
